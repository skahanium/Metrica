# 维护者规则

本项目采用轻量维护者模型。治理目标是降低个人维护负担，同时让贡献者知道谁可以做决定、决定如何被记录。

## 维护者职责

维护者负责：

- 确认项目范围和当前阶段优先级。
- 分流 Issue、维护标签、关闭不符合阶段目标的请求。
- Review 和合并 PR。
- 执行发布前质量门禁和创建 release。
- 处理安全报告并决定披露节奏。
- 对架构边界、协议变更和破坏性变更作最终判断。

## 贡献者与 reviewer

贡献者可以提交 Issue、PR、测试、文档和验证结果。活跃贡献者可以参与 review，但 review 通过不自动等于合并许可。

在正式建立多维护者团队前，合并权和发布权由项目维护者保留。

## 决策方式

- 小修复：通过 PR review 决定。
- 用户可见行为或文档承诺变化：在 PR 描述中写明影响。
- 架构边界、协议、版本策略、支持策略或破坏性变更：使用决策记录。

当意见不一致时，维护者应给出简短理由，并优先选择符合当前阶段、可验证、维护成本较低的方案。
