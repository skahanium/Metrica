# 决策：采用轻量发布与治理流程

日期：2026-05-17
状态：accepted

## 背景

Metrica 正从大量实现推进到外部可协作状态，但项目仍由个人开发者兼职维护。完整基金会式治理、自动发布矩阵和多维护者制度会增加过早负担。

## 决定

第三阶段只建立最小必要规则：

- 采用 `0.x` 线上的轻量 SemVer。
- 使用手动 release checklist，不引入自动发布流水线。
- 明确支持范围为最新 `main` 和最新 tagged release（若存在）。
- 保留单一维护者最终决策权。
- 仅对架构、协议、破坏性变更和治理变化使用 ADR/RFC 记录。

## 权衡

收益是规则清晰、维护成本低、外部贡献者知道如何参与。成本是 release 自动化、长期支持分支和多维护者授权暂未建立。

## 影响

发布前需要检查版本、支持和治理文档是否一致。贡献者提出破坏性变更时，应先补充决策记录或 Issue 说明。
