# Metrica 交互纯粹化设计

## Context

当前 Metrica 计量功能（S1-S4）已全部实现，但交互层存在严重的范式混杂：
文本公式输入、下拉菜单、按钮、Tab 切换四种交互模式平等共存，用户完成一次回归需要
在四种模式之间反复切换。根本问题不是缺功能，而是缺一个主导的交互哲学。

本次设计的目标：以**变量为原语 + 常驻命令行**为核心，建立统一的交互范式，
消除多范式撕裂感，同时加入教学层使产品区别于 Stata。

## 核心原则

1. **建模走纯 CLI**：回归、诊断、检验、预测等分析操作，命令行是唯一入口。
   消除 ModelForm 中的下拉选模型、填参数、输公式等混杂交互。
2. **数据操作双通道**：数据查看、列操作、变换可走 CLI 命令也可走可视化鼠标操作，
   两者等价且可互相替代。
3. **变量是原语**：变量在侧边栏以缩略卡片展示，在数据全屏视图中可完整交互，
   在命令行补全中作为第一等候选。
4. **结果流 + 展开**：结果是向上滚动的分析历史流。图表可点击展开至全宽或弹出大窗。
   空间计量地图自动以全宽模式渲染。
5. **可开关教学层**：在结果上叠加解释卡片（模型方程、拟合优度解读、诊断含义、
   下一步建议），默认对新手开启。

## 命令系统

### 命令语法

```
命令动词  参数...  [, 选项...]
```

三条铁律：

1. **参数在前，选项在后，逗号严格分隔。** 逗号之前全是位置参数（变量名或表达式），
   逗号之后全是命名选项。`regress y robust` 中 `robust` 是变量；
   `regress y, robust` 中 `robust` 是选项。解析器和补全都依赖这一分隔。
2. **选项统一为键值风格。** 无参数选项如 `robust` 等价于 `robust(true)`；
   有参数选项如 `cluster(region)`。不用 `fe`/`re` 等裸缩写——统一为
   `method(fe)` / `method(re)`。
3. **因变量永远在第一参数位置。** 自认为模型的结构参数（id、time、treatment）永远
   在选项区。这样参数区只描述变量在等式中的角色，不含混。

### 命令分类

| 类别 | 命令示例 |
|------|---------|
| 数据加载 | `use "path/to/data.csv"`, `use clear` |
| 数据查看 | `describe`, `browse`, `summarize gdp infl`, `tabulate year` |

| 线性模型 | `regress y x1 x2`, `regress y x1 x2, robust` `regress y x1 x2, cluster(region)`, `ivregress y x1 x2, endogenous(x1) instruments(z1 z2)`, `gls y x1 x2, weights(w)` |
| 面板模型 | `xtreg y x1 x2, id(country) time(year) method(fe)`, `xtreg y x1 x2, id(country) time(year) method(re)`, `xtreg y x1 x2, id(country) time(year) method(fd)`, `xtivreg y x1 x2, id(country) time(year) method(fe) endogenous(x1) instruments(z1)` |
| 离散模型 | `logit y x1 x2`, `logit y x1 x2, robust`, `probit y x1 x2`, `poisson y x1 x2`, `ologit y x1 x2`, `mlogit y x1 x2`, `nbreg y x1 x2` |

| 后估计 | `predict yhat, xb`, `predict resid, residuals`, `margins`, `margins, at(means)`, `test x1 = x2`, `lincom x1 + 2*x2`, `estimates store m1`, `estimates restore m1` |

### 数据查看命令的当前实现约束

- `describe`：结果流展示数据集规模与变量元数据，不伪造 Stata 的 label / format / value label 列。
- `summarize`：结果流展示 `Obs / Mean / Std. dev. / Min / Max`，字符串变量保留行但数值统计为空。
- `tabulate`：当前只支持单变量 one-way 频数表，默认排除缺失值并返回累计百分比。
- `browse`：不在结果流里渲染“预览卡片”，而是切换到只读数据全屏视图，并按 varlist 过滤列。

### 自动补全：基于语法树的上下文补全

补全不是按"命令→语法→变量→选项"的顺序猜阶段——用户会随时跳跃修改
命令的任意部分。补全系统需要**实时解析光标位置在命令语法树中的节点**，
根据节点类型决定补全内容。

#### 语法树模型

每个命令动词有一棵语法树，以 `regress` 为例：

```
regress ─ 因变量(必填,1) ─ 自变量*(零或多) ── [,] ── 选项*(零或多)
                                                    ├─ robust
                                                    ├─ cluster(─ 变量(必填,1) ─)
                                                    └─ noconstant
```

`ivregress` 的语法树：

```
ivregress ─ 因变量(必填,1) ─ 自变量*(零或多) ─ [,] ── 选项*(零或多)
                                                     ├─ endogenous(─ 变量(必填,1+) ─)
                                                     ├─ instruments(─ 变量(必填,1+) ─)
                                                     ├─ robust
                                                     └─ cluster(─ 变量(必填,1) ─)
```

`xtreg` 的语法树：

```
xtreg ─ 因变量(必填,1) ─ 自变量*(零或多) ─ [,] ── 选项*(零或多)
                                                 ├─ id(─ 变量(必填,1) ─)      [必填]
                                                 ├─ time(─ 变量(必填,1) ─)    [必填]
                                                 ├─ method(─ fe|re|fd|between|hdfe|cre ─) [必填]
                                                 ├─ robust
                                                 └─ cluster(─ 变量(必填,1) ─)
```

#### 上下文补全行为

光标所在节点决定补全内容和排序：

| 光标位置 | 补全内容 | 排序策略 |
|---------|---------|---------|
| 命令动词 | 所有命令动词 | 按使用频次降序 |
| 因变量 | 所有变量 | 连续型优先，标注"常用作因变量" |
| 自变量 | 所有变量 | 最近使用优先，不限制类型 |
| `,` 后的选项区 | 该命令的合法选项 | 必填选项优先并标注 |
| `cluster()` / `id()` / `strata()` 括号内 | 所有变量 | 离散型优先，分类变量置顶 |
| `endogenous()` / `instruments()` 括号内 | 所有变量 | 不限类型 |
| `method()` / `ar()` / `i()` / `ma()` 括号内 | 枚举值 / 数字范围 | 显示合法取值 + 中文说明 |

```
> regress |                          (光标在因变量节点)
  ┌─ 因变量 ───────────────────────────────────────────┐
  │ ▸ gdp        连续  μ=4.32  [← 常用作因变量]        │
  │ ▸ trade      连续  μ=5.32                          │
  │ ▸ inflation  连续  μ=2.10                          │
  │ ▸ year       离散  n=5                             │
  │ ▸ region     离散  n=8                             │
  └────────────────────────────────────────────────────┘

> ivregress gdp inflation year, endogenous(|)
  ┌─ endogenous 变量 ──────────────────────────────────┐
  │ ▸ inflation   连续  ← 已在模型中                    │
  │ ▸ trade       连续                                  │
  │ ▸ year        离散                                  │
  └────────────────────────────────────────────────────┘

> xtreg gdp inflation, id(|)
  ┌─ id 变量 ──────────────────────────────────────────┐
  │ ▸ country     离散  n=150    ← 面板标识,每单元多期  │
  │ ▸ region      离散  n=8      ← 层级较少,可能不合适  │
  │ ▸ year        离散  n=30                           │
  └────────────────────────────────────────────────────┘
```

**关键行为：**
- 补全菜单内联在光标上方，不遮挡命令行
- `id()` / `time()` 括号内的补全附带语义提示（"面板标识" / "时间维度"）
- 已在参数区使用过的变量在补全中显示 `← 已在模型中`，不阻止但示意
- Tab 接受第一条补全，Shift+Tab 回退；↑↓ 浏览；Enter 接受选中项并自动补逗号
  （如从因变量补全接受后，光标自动跳到自变量位置）

#### 幽灵文本

补全菜单之外，命令行内出现**灰色幽灵文本**，预览最可能的补全结果：

```
> regress gdp inflation year, robust cluster(region)          ← 灰色
                                    ^^^^^^^^^^^^^^^^
```

- 幽灵文本 = 当前上下文下最高置信度的单条补全
- Tab 接受幽灵文本，继续输入任意字符则消失
- 幽灵文本在用户停顿 300ms 后出现
- 适用于熟练用户：不看补全菜单，Tab 一路到底

#### 纠错

变量名拼写错误时，补全不返回空——而是返回最接近的实际变量名：

```
> regress gdp inflaton |
  ┌─ 未找到 "inflaton"。你的意思是？ ───────────────────┐
  │ ▸ inflation   连续  μ=2.10  (编辑距离: 2)            │
  └─────────────────────────────────────────────────────┘
```

使用 Levenshtein 编辑距离 ≤ 3 的变量名作为纠错建议。

#### 补全有效性度量

| 指标 | 目标 | 测试方式 |
|------|------|---------|
| Top-3 命中率 | > 90%（期望补全出现在前三条） | 计量教材标准习题的命令序列 |
| 按键节省率 | 输入字符 / 命令全长 < 60% | 同上测试集 |
| 纠错命中率 | 拼写错误时正确变量在前三 > 80% | 注入 2-3 字符拼写错误 |

### 教学层

- 每个结果块的顶部和关键输出之间插入教学卡片
- 卡片内容因模型类型而异：OLS 解释 R²，Logit 解释 Odds Ratio 和边际效应，
  DID 解释平行趋势假设和处理效应
- 命令行旁有教学开关 `[📖 开/关]`，状态持久化
- 教学卡片可折叠，折叠后仅留一行摘要
- 教学内容由 Julia 后端生成（`ModelResult.teaching_notes`），而非前端硬编码

## 命令解析与分发

```
用户输入命令字符串
       │
       ▼
┌─ CommandParser ───────────┐
│ 1. Tokenize               │
│ 2. 识别命令动词            │
│ 3. 分离位置参数和选项      │
│ 4. 验证变量名存在          │
│ 5. 输出 ParsedCommand      │
└──────────┬────────────────┘
           │
           ▼
┌─ CommandDispatcher ──────┐
│ 根据命令动词路由:          │
│  - 建模命令 → ModelSpec    │
│  - 数据命令 → DataOp       │
│  - 项目命令 → ProjectOp    │
│  - 导出命令 → ExportOp     │
└──────────┬────────────────┘
           │
           ▼
   现有 runtimeClient API
   (fitModel / transform / saveProject / exportReport / ...)
```

- `CommandParser` 在前端完成，实时反馈语法错误
- `CommandDispatcher` 将解析后的命令映射到现有 API 调用
- 建模命令翻译为 `ModelSpec`（复用现有 `buildModelSpec` 逻辑）
- 数据操作命令翻译为 `DataOp`（复用现有 `transformStore` 逻辑）

## 交互流示例

### 典型回归分析

1. `> use "data/GDP.csv"` → 加载数据，侧边栏显示变量列表，主内容区显示数据全屏视图
2. 浏览数据视图，查看各列统计，右键删除不需要的列
3. `> describe` → 结果流显示数据集规模与变量元数据
4. `> browse inflation year` → 切换到只读数据全屏视图，并仅显示 `inflation` 与 `year`
5. `> regress gdp inflation year, robust` → 结果流显示回归结果 + 教学层解释
6. 点击残差直方图 → 展开为大图查看
7. `> ovtest` → 对上一模型执行 RESET 检验，结果追加到流
8. `> export markdown` → 导出完整分析报告

## 验证计划

1. **命令解析单元测试**：覆盖所有命令动词的 Tokenize、参数/选项分离、变量存在性验证；
   IV 括号语法已弃用验证；逗号分隔严格性验证
2. **语法树构建测试**：每个命令动词的语法树结构验证；光标位置→节点类型映射正确性
3. **补全引擎测试**：上下文补全（命令动词/因变量/自变量/选项/括号内，共 6 种上下文）；
   语义排序（因变量优先连续型、cluster优先离散型）；幽灵文本生成；纠错建议（编辑距离 ≤ 3）
4. **补全度量测试**：Top-3 命中率、按键节省率、纠错命中率，用标准计量习题命令集打分
5. **命令分发测试**：验证 ParsedCommand → ModelSpec/DataOp 的翻译正确性；
   所有模型命令的字段映射完整性
6. **数据全屏视图**：启动 dev server，加载数据集，验证表格渲染、排序、筛选、
   列选择、列信息卡片
7. **结果流**：执行回归，验证结果块渲染、教学层开关、图表展开/收起
8. **端到端**：完整走通 `use → describe → browse → regress → test → export` 流程
